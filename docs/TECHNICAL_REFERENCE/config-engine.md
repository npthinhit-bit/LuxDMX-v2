# Config Engine — Technical Reference

Domain: cfg.config-engine

## 1. Domain Scope

The config engine resolves, persists, and exposes the firmware's runtime configuration. It owns the **single source of truth** for what settings exist, their constraints, and their human-facing metadata — the `CONFIG_FIELDS[]` and `OUTPUT_FIELDS[]` tables in `src/cfg/config_schema.cpp`. No defaults live in the schema: defaults come from board templates (`templates/*.ini`).

**Owns**: template resolution, NVS load/save, field-by-field set/get/dump, JSON/XML import/export, serial-console command grammar, one-shot NVS key migration (`/config` and `sacn` namespaces), and build-time template embedding.

**Delegates**: template data is generated by `tools/gen_config_templates.py` from `templates/*.ini`; persistence uses ESP-IDF `Preferences.h` (NVS key-value store); serial console is driven by `cfgserial::poll()` called from `main.cpp:135`.

**Consumed by**: `main.cpp` (`load()` at `main.cpp:46`, `migrateNvsKeys()` at `main.cpp:45`, `serial.begin` at `main.cpp:50`), `src/net/web_routes.cpp` (`importJson` at `web_routes.cpp:180`, `setValue` at `web_routes.cpp:246`), `src/net/artnet_bridge.cpp:103` (`saveConfig`), `src/net/net_state.cpp:101` (`saveConfig`), and every module that reads `cfg.*` globals.

## 2. Layer Mapping

```
drv  →  cfg  →  core  →  net  →  app/sys
              ↑
        config-engine (this module)
```

The cfg layer sits between the drivers (which consume resolved pins) and the core/net/sys layers (which consume the `cfg` singleton). It is the **only** module that reads/writes NVS for application settings.

## 5. Concurrency

Single-threaded at the cfg layer level. `cfgcore::load()` and `save()` are called once at boot (`main.cpp:46`) and from core-0 contexts only (`web_routes.cpp:180`, `artnet_bridge.cpp:103`, `net_state.cpp:101`). `Preferences` (NVS) calls are blocking but only from core 0. `cfgserial::poll()` runs in `loop()` on core 0 (`main.cpp:135`). No locking is used — the `cfg` singleton is not concurrently mutated from core 1.

The cross-core seqlock used for DMX frame data lives in [include-headers](./include-headers.md) (`seqlock.h`) and is consumed by `core-dmx-buffer.md`, not this module.

## 6. State Machine

No state machine — stateless request/response. `setValue`/`getValue`/`save`/`load` are pure functions of the current `cfg` contents and the NVS key space. The serial console parser in `execute()` (`config_serial.cpp:53`) is a single-pass state machine over one input line: it tokenizes by whitespace/comma (`config_core.cpp:37–40` equivalent in `applyKv` at `config_serial.cpp:37–40`), splits on `=`, and dispatches to a verb handler.

## 8. Data Flow

1. **Boot**: `main.cpp:45` calls `migrateNvsKeys("dmxgw")` → opens NVS namespace `"dmxgw"` (`config_core.cpp:15`) → iterates `OUTPUT_FIELDS` (`config_schema.cpp:153`) comparing old `o0_*/o1_*` keys to new `a_*/b_*` keys → copies values and erases old keys (`nvs_migrate.cpp:19–38`); then migrates scene keys in the `"scenes"` namespace (`nvs_migrate.cpp:57–91`).
2. **Template resolution**: `cfgcore::load()` (`config_core.cpp:167`) calls `resetToTemplate()` (`config_core.cpp:157`) → `applyNeutral()` fills every field with its neutral value (`config_core.cpp:102–116`) → `applyTemplate(DEFAULT_TEMPLATE, ...)` (`config_core.cpp:155`) resolves the `DEFAULT_TEMPLATE` macro (`config_core.cpp:19`) → `applyNamed()` (`config_core.cpp:146`) looks up `CONFIG_TEMPLATES[]` (generated from `templates/*.ini` by `gen_config_templates.py:60`) → `applyTemplateText()` (`config_core.cpp:120`) parses line-by-line, handles `extends=` inheritance (`config_core.cpp:140`), and calls `setValue()` for each `key=value` pair.
3. **NVS overlay**: after template application, `load()` re-opens NVS (`config_core.cpp:170`) and overlays each field from `prefs.getInt`/`getBool`/`getString` (`config_core.cpp:173–175` for globals, `config_core.cpp:177–205` for outputs), clamping to `[min, max]` via `constrain()` (`config_core.cpp:175`, `config_core.cpp:204`).
4. **Runtime mutation (serial)**: `loop()` → `main.cpp:135` → `cfgserial::poll()` (`config_serial.cpp:99`) reads bytes from `Serial` into `g_line` (`config_serial.cpp:6`) → on newline calls `execute(g_line)` (`config_serial.cpp:110`) → dispatches to `applyKv()` (for `key=value` tokens, `config_serial.cpp:33`) or `cfgcore::setValue()` (`config_serial.cpp:78`) → returns `"OK"` or `"ERR ..."` string to the serial port.
5. **Runtime mutation (web)**: `web_routes.cpp:180` → `cfgcore::importJson(body, err)` (`config_core.cpp:290`) scans JSON for `"key":"value"` or `"key":value pairs (`config_core.cpp:299–333`) → calls `setValue()` (`config_core.cpp:91`) → if `artNet().artCfgDirty`, `saveConfig()` is called (`main.cpp:142`).
6. **Persistence (save)**: `cfgcore::save()` (`config_core.cpp:213`) iterates `CONFIG_FIELDS` (`config_schema.cpp:46`) writing each to NVS via `prefs.putBool`/`putString`/`putInt` (`config_core.cpp:217–219`) → iterates `OUTPUT_FIELDS` for each of `MAX_OUTPUTS` outputs (`config_core.cpp:221–227`) → writes `apfb` boolean for backward compat (`config_core.cpp:228`).
7. **Export (JSON)**: `cfgcore::exportJson()` (`config_core.cpp:249`) iterates both descriptor tables, masking `CFG_SECRET` fields (`config_core.cpp:257, 279`) → returns to web handler for `/info.json` or `/config GET`.
8. **Template change (web)**: `web_routes.cpp` calls `cfgcore::resetTo(name, err)` (`config_core.cpp:162`) → `applyNeutral()` + `applyTemplate(name)` → caller triggers `saveConfig()` then reboot if `CFG_REBOOT` fields differ.

## 9. Protocol Layout

**Template INI format** (parsed by `applyTemplateText` at `config_core.cpp:120`):

```
key=value                  # config_core.cpp:135  — stripped of leading/trailing whitespace
extends=_base             # config_core.cpp:140   — recursive template inheritance (max depth 8)
# comment                  # config_core.cpp:134  — ignored
(blank line)              # config_core.cpp:134  — ignored
```

Parsing rules:
- Line buffer is 192 bytes (`config_core.cpp:122`); lines exceeding 191 chars are truncated (`config_core.cpp:127`).
- Leading/trailing whitespace and `\r` stripped (`config_core.cpp:131–133`).
- `extends=` values resolve via `applyNamed()` looking up `CONFIG_TEMPLATES[]` (`config_core.cpp:146–149`).
- Recursion depth cap: 8 (`config_core.cpp:121`).

**NVS key naming scheme** (namespace `"dmxgw"` from `load()`/`save()` at `config_core.cpp:170, 214`):

| Scope | Key format | Source |
|---|---|---|
| Global fields | `f.key` (e.g. `"hostname"`, `"ledtype"`) | `CONFIG_FIELDS[j].key` (`config_schema.cpp:47-131`) |
| Output A–D fields | `a_<suffix>`, `b_<suffix>`, `c_<suffix>`, `d_<suffix>` | `outKey(i, suffix)` at `config_core.cpp:30` |
| Output legacy (0–1 only) | `o0_<suffix>`, `o1_<suffix>` | `outKeyLegacy(i, suffix)` at `config_core.cpp:34`; migrated away at `config_core.cpp:182–196` |
| Link-loss policy (legacy) | `apfb` (bool) | migrated to `fbmode` at `nvs_migrate.cpp:43–48` and `config_core.cpp:206–207` |

**Serial console grammar** (parsed by `cfgserial::execute()` at `config_serial.cpp:53`):

```
dump                     → prints "key=value\n" for every field (config_serial.cpp:66, config_core.cpp:232)
key=value [key=value...] → sets one or more fields via applyKv (config_serial.cpp:62)
get <key>                → prints "key=value" (config_serial.cpp:67-70)
set <key> <value>        → prints "OK" or "ERR <msg>" (config_serial.cpp:72-79)
save [reboot]            → persists to NVS; reboots if "reboot" given (config_serial.cpp:80-84)
wifi <ssid> [pass]       → calls hooks.wifi callback (config_serial.cpp:85-93)
reboot                   → calls hooks.reboot callback (config_serial.cpp:94)
factory                  → calls hooks.factory callback (config_serial.cpp:95)
help / ?                 → prints helpText (config_serial.cpp:65)
```

**JSON import format** (parsed by `importJson()` at `config_core.cpp:290`): line-based scan for `"key":"value"` (line 301–319) or `"key":value` (line 322–331). Not a full JSON parser — handles flat object with simple values.

**XML export format** (emitted by `exportXml()` at `config_core.cpp:338`): `<config><global>...<tag>value</tag>...</global><outputs>...<output index="0">...<tag>value</tag>...</output>...</outputs></config>`.

## 10. Config Integration

This module **is** the config integration layer. Every `Config` field and `DmxOutput` field is described in `CONFIG_FIELDS[]` (`config_schema.cpp:46–133`) and `OUTPUT_FIELDS[]` (`config_schema.cpp:153–178`). The `flags` bitmask determines live vs reboot semantics:

- **`CFG_REBOOT`** (default via `IFIELD`/`BFIELD`/`EFIELD` macros, `config_schema.cpp:30–36`): pins, LED type/pin, display pins, encoder/button pins, network mode, WiFi SSID, static IP, VLAN, syslog port, etc. Require a reboot to take effect.
- **`CFG_LIVE`** (via `*_L` macros, `config_schema.cpp:38–44`): universe, net, subnet, sACN universe/sync, merge mode, loss mode, loss preset, failsafe timeout, TX rate/style/source, break/MAB, invert, input mode, split mask, loopback, brightness, protocol, board, ipProg, autoIp, dscp, timecode, syslog, webhook, artnetRdm. Apply instantly.
- **`CFG_SECRET`**: `otapw` (`config_schema.cpp:49`), `wifipsk` (`config_schema.cpp:106`), `apPassword` (`config_schema.cpp:108`), `webhookUrl` (`config_schema.cpp:128`) — masked to `"***"` in `dump()` (`config_core.cpp:236–237`) and `exportJson()` (`config_core.cpp:257`).
- **`CFG_NOWEB`**: `autoUpdate` (`config_schema.cpp:131`) — not in the `/config` form.
- **`CFG_READONLY`**: none currently assigned.
- **`CFG_KEEPNE`**: `hostname` (`config_schema.cpp:47`), `otapw` (`config_schema.cpp:49`), `wifipsk` (`config_schema.cpp:106`) — blank web form fields are ignored, never cleared.

The resolution order at boot is: neutral (from constraint) → active board template (`DEFAULT_TEMPLATE`) → saved NVS value (`config_core.cpp:167–168`). Board templates are selected per-build via `-DDEFAULT_TEMPLATE=<name>` in `platformio.ini` (e.g. `esp32s3_psram` at `platformio.ini:155`, `luxdmx_4uni` at `platformio.ini:167`).

## 11. Lifecycle

1. **Compile time** — `extra_scripts.py:132` invokes `tools/gen_config_templates.py` which reads `templates/*.ini` (sorted `_base` first at `gen_config_templates.py:40`) and emits `src/generated/config_templates.gen.h` with `static const char` template strings + `CONFIG_TEMPLATES[]` registry (`gen_config_templates.py:54–62`). `src/config_templates_gen.cpp:3` includes this header so it compiles into every firmware build.
2. **NVS migration** — `main.cpp:45` calls `migrateNvsKeys("dmxgw")` — one-shot, idempotent, no-op after first run (`nvs_migrate.cpp:14`).
3. **Config load** — `main.cpp:46` calls `cfgcore::load()` → `resetToTemplate()` → `applyNeutral()` → `applyTemplate(DEFAULT_TEMPLATE)` → NVS overlay.
4. **Output sanitization** — `main.cpp:47` calls `sanitizeOutputs()` (`output_init.cpp:8`) to clamp/validate per-output pin sets against the board template.
5. **Serial console begin** — `main.cpp:50` calls `cfgserial::begin(Serial, {})` with empty hooks (no save/reboot/factory/wifi callbacks registered at init).
6. **Main loop** — `main.cpp:135` calls `cfgserial::poll()` every loop iteration; dirty-flag persistence at `main.cpp:142` calls `saveConfig()` when `artNet().artCfgDirty` is true.

## 12. Error Handling

- `setValue()` returns `ESP_ERR_INVALID_ARG` (`config_core.cpp:90`) — logs via `ESP_LOGE("cfgcore", "unknown key: %s")` (`config_core.cpp:90`); sets `err` output string.
- `getValue()` returns `ESP_ERR_INVALID_ARG` (`config_core.cpp:97`) — logs via `ESP_LOGE("cfgcore", "key not found: %s")`.
- `applyTemplateText()` returns `ESP_ERR_INVALID_STATE` on nesting > 8 (`config_core.cpp:121`); returns `ESP_ERR_INVALID_ARG` if a `setValue` call inside the template fails (`config_core.cpp:141`).
- `applyNamed()` returns `ESP_ERR_NOT_FOUND` on unknown template (`config_core.cpp:152`); logs via `ESP_LOGE("cfgcore", "unknown template: %s")` (`config_core.cpp:150`).
- `importJson()` returns `ESP_ERR_INVALID_ARG` if any key unrecognized (`config_core.cpp:334`); logs via `ESP_LOGE("cfgcore", "importJson: some keys not recognized")`.
- `importXml()` returns `ESP_ERR_INVALID_ARG` if any key unrecognized (`config_core.cpp:394`).
- `load()` and `save()` do not return errors — they assume NVS always succeeds (ESP-IDF `Preferences` returns 0 on failure, which is treated as "use the neutral/template value" for int fields at `config_core.cpp:175`).
- `cfgserial::execute()` returns `"ERR <msg>"` strings (`config_serial.cpp:49, 70, 96`); unknown commands return `"ERR unknown command: <verb> (try 'help')"` (`config_serial.cpp:96`).
- Int values are clamped to `[min, max]` via Arduino `constrain()` in `writeTyped` (`config_core.cpp:47`) and during `load()` (`config_core.cpp:175`, `config_core.cpp:204`).

## 13. Allocation

All data structures are **static**:

- `Config cfg` is a static global (`config_core.cpp:12`) — no heap allocation for config values. `String` fields (`Arduino.h`) grow on the heap individually, but the struct layout is fixed.
- `CONFIG_FIELDS[]` is `static const` in `.rodata` (`config_schema.cpp:46`); `OUTPUT_FIELDS[]` at `config_schema.cpp:153`.
- Template strings (`static const char T_*[]`) are in `.rodata` — generated as non-PROGMEM by `gen_config_templates.py:51` (comment: "on ESP32 const .rodata lives in memory-mapped flash and is directly readable").
- `CfgTemplate` registry is a static array in `.rodata` (`gen_config_templates.py:60`).
- `OUT_KEY_PREFIXES[]` / `OUT_KEY_LEGACY[]` are `static const` (`config_core.cpp:24–25`).
- Serial console globals (`g_io`, `g_hooks`, `g_line`, `g_announced`) are static at `config_serial.cpp:6–9`.
- `g_line` is capped at 600 chars (`config_serial.cpp:113`).
- NVS handle is opened/closed per call in `load()` and `save()` (`config_core.cpp:170`, `config_core.cpp:208`, `config_core.cpp:214`, `config_core.cpp:229`) — no persistent persistent handle.

## 14. Timing

- `cfgserial::poll()` is non-blocking: it drains at most one serial character per `available()` iteration (`config_serial.cpp:105–115`); called each `loop()` cycle. The 600-char input cap (`config_serial.cpp:113`) bounds worst-case line accumulation.
- `load()` and `save()` iterate `CONFIG_FIELD_COUNT` + `OUTPUT_FIELD_COUNT × MAX_OUTPUTS` fields — both are bounded and small (62 global fields + 24 output fields × 4 outputs = ~158 NVS operations). No timing constraint specified; NVS wear is one full save per config change (triggered lazily via dirty flags at `main.cpp:142`).
- `migrateNvsKeys()` is one-shot at boot — not a recurring cost.

## 17. Limitations

- `load()` and `save()` return `void` — NVS failures (e.g. flash corruption) are silently swallowed; `Preferences.getInt` returns 0 on failure, which `load()` treats as "use the neutral/template value" (`config_core.cpp:175`). No error propagation.
- `importJson()` is a line-based scanner, not a conformant JSON parser (`config_core.cpp:290`) — nested objects, arrays of objects (other than `outputs`), escaped characters, and comments are not handled.
- `importXml()` is even more minimal — it tokenizes by `<` / `>` and tag names are used directly as config keys (`config_core.cpp:367–395`); malformed XML produces silent failures.
- `CFG_NOWEB` fields are excluded from the `/config` form but `importJson` will still set them if a caller sends them — no runtime web-layer filtering.
- Template line buffer is fixed at 192 bytes (`config_core.cpp:122`); a template line exceeding 191 visible characters is silently truncated.
- `migrateNvsKeys()` only migrates outputs 0–1 (`nvs_migrate.cpp:19`); outputs 2–3 had no legacy keys to migrate (they didn't exist in the old 2-output build).
- `cfgserial::begin()` is called with empty `Hooks` at `main.cpp:50` — the save/reboot/factory/wifi commands print `"ERR wifi not available"` / `"OK saved"` without actually triggering hardware actions unless hooks are registered later.
- Scene key migration in `nvs_migrate.cpp:57–91` depends on `MAX_SCENES` (`scene_engine.h:15`) and `DMX_PACKET_SIZE` (`rdm_types.h:33`) — a scene struct size change requires coordinated updates in `scene_engine.h`, `nvs_migrate.cpp:83`, and `scene_engine.cpp`.

## 20. History

- `Config` and `DmxOutput` structs moved from `main.cpp` into `include/config_schema.h` to make them includable by all layers (`config_schema.h:4–5` comment).
- NVS key scheme changed from per-output `o0_*`/`o1_*` (2-output builds) to letter-prefixed `a_*`/`b_*`/`c_*`/`d_*` (4-output builds) — `nvs_migrate.cpp:4–10` comment describes the one-shot migration.
- `apfb` boolean migrated to `fbmode` enum to support the 4-policy link-loss fallback (`WIRED_FB_RETRY/AP/REBOOT/WIFI`) at `config_enums.h:9` — migration code at `config_core.cpp:206–207` and `nvs_migrate.cpp:43–48`.
- Scene NVS keys namespaced from `s{idx}*` to `scn_s{idx}*` to avoid future key collisions (`nvs_migrate.cpp:52–56` comment).
- Template-based config defaults replaced scattered `DEF_*` macros in `main.cpp` — templates are now data files (`templates/*.ini`) embedded at build time (`gen_config_templates.py:3–7`).
- JSON import/export added to support the web `/config` POST endpoint (`config_core.cpp:249–336`).
- `DEFAULT_TEMPLATE` moved from `-D` macro in `platformio.ini` to a per-environment build flag (e.g. `platformio.ini:155`, `platformio.ini:167`).
