# M0.4.4.1 — Generated assets inventory and decision record

**Dự án:** LuxDMX-v2  
**Milestone:** M0.4.4  
**Work package:** M0.4.4.1 — Inventory generated assets và decision record  
**Ngày:** 22-08-2026  
**Baseline:** `4079455 ci: close firmware artifact matrix validation`  
**Trạng thái:** Hoàn tất inventory; chưa thêm generator, generated output hoặc build hook

## 1. Quyết định

Repository hiện **chưa có một generator tổng quát được tích hợp vào build**. Không có `extra_scripts`, custom generation command, generated include directory hoặc custom CMake generation rule trong build path hiện tại. Vì vậy M0.4.4.1 chỉ ghi nhận code reality và xác định contract tiếp theo; không tạo header giả, không copy `webui/` vào firmware và không gắn hook dựa trên mô tả trong system specification בלבד.

Có hai nhóm cần xử lý ở các work package sau:

1. **Board template inputs:** Các file `templates/*.ini` là source-of-truth dự kiến, nhưng runtime hiện đang dùng một bản sao inline trong `components/lux_config/src/config_schema.c`. Cần M0.4.4.2–M0.4.4.3 thiết kế generator và chuyển consumer một cách có kiểm chứng.
2. **Web/static assets:** `webui/` là source tree được track, nhưng runtime hiện trả về các C string được viết trực tiếp trong `web_frontend.c` và `web_assets.c`. Chưa có bằng chứng `webui/` được consumer trực tiếp trong firmware; việc sinh PROGMEM header phải chờ một decision record riêng sau khi xác định mapping và byte contract.

> **Boundary:** System specifications mô tả generator như kiến trúc mục tiêu; file specification không phải bằng chứng rằng generator đã tồn tại trong checkout hiện tại. Mọi generator mới phải có input explicit, consumer thật, output manifest và double-run reproducibility test.

## 4. Current generated-file policy

M0.4.1/M0.4.2 đã thiết lập hygiene và diagnostics cho output build, sdkconfig, firmware artifact và secrets. M0.4.4 không được nới lỏng policy đó. Generated output mới phải nằm trong build/temp namespace, không được track nếu không có quyết định source-of-truth rõ ràng, và phải có manifest để phân biệt output hợp lệ với file rác.

Generator tương lai phải đáp ứng tối thiểu:

| Contract | Quyết định inventory |
|---|---|
| Input root | Repository-relative root explicit; không quét ngầm toàn filesystem |
| Input allowlist | Chỉ đọc các file đã manifest hóa; symlink và path traversal bị từ chối |
| Encoding | UTF-8 rõ ràng; lỗi decode là hard failure |
| Ordering | Sort ổn định, không phụ thuộc filesystem order hoặc locale |
| `extends` | Base-first, depth cap, missing parent/cycle detection |
| Output path | Build-generated namespace theo environment; không ghi source tree |
| Reproducibility | Cùng input phải cho cùng file list, bytes, size và SHA-256 |
| Metadata | Không timestamp, hostname, username, absolute path hoặc random value |
| Failure | Non-zero và không để lại partial output |
| Manifest | Versioned UTF-8 JSON, stable key order, input/output hashes, error list |
| Security | Không dump process environment, token, key hoặc password |

## 5. Scope boundary cho các package tiếp theo

### M0.4.4.2 — Pure generator CLI

Chỉ tạo CLI host-side và manifest schema trên input fixture nhỏ. Package này chưa được phép thay đổi runtime consumer nếu chưa có golden output và test failure cases.

### M0.4.4.3 — Template generator

Chuyển template inheritance thành logic deterministic có test cho base/override, missing parent, cycle, duplicate key, malformed line và depth limit. Chỉ sau khi output khớp consumer mới thêm build integration.

### M0.4.4.4 — Web/static asset generator

Chỉ thực hiện nếu xác định được `webui/` là canonical source và có thể đối chiếu byte output với inline runtime assets. Nếu không, package phải được đánh dấu blocked/documented-only thay vì sinh output không được consume.

### M0.4.4.5–M0.4.4.7

Sau khi có pure generator và consumer thật mới tích hợp PlatformIO/CMake hook, determinism checker và CI gate. Không được đảo thứ tự để dùng CI làm bằng chứng cho một contract chưa ổn định.

## 6. Acceptance criteria của M0.4.4.1

M0.4.4.1 đạt khi inventory xác định được source-of-truth, output và consumer cho từng nhóm; mọi generator/build hook hiện hữu hoặc vắng mặt được ghi nhận bằng evidence; các asset chưa có consumer được đánh dấu rõ; và không có source/runtime behavior nào bị thay đổi trong package này.

Validation thực hiện:

```text
git grep -n -I -E 'extra_scripts|generated|PROGMEM|template|extends|web_assets_get|web_frontend_get'
find templates webui -maxdepth 2 -type f -printf '%p\t%s bytes\n' | sort
python3 tools/repository_hygiene.py --tracked-only
git diff --check
```
