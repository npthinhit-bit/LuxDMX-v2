# M0.4.5.1 — Web boundary baseline and route/resource freeze

**Dự án:** LuxDMX-v2  
**Ngày freeze:** 24-08-2026  
**Baseline commit:** `a6711cad46fdf9cccf2333cba4d628575afb630a` (`docs: record web asset generator boundary`)  
**Trạng thái:** Inventory snapshot only; không chọn canonical source và không thay đổi runtime web.

## 1. Mục đích và giới hạn

Tài liệu này đóng băng hiện trạng web surface trước khi lập parity matrix và quyết định viết lại/migrate web. Nó liệt kê các route được đăng ký từ firmware HTTP server, OTA manager và WebSocket module; các HTML/CSS/JavaScript resources; các file `webui/`; source/build registration đang consume chúng; cùng fingerprint có thể tái tạo từ baseline.

> **Không suy diễn:** Route được đăng ký không đồng nghĩa frontend đã đúng thiết kế LuxDMX. File tồn tại trong `webui/` không đồng nghĩa firmware đang serve file đó. Canonical source chỉ được chọn ở M0.4.5.3 sau khi route/API/DOM parity được đối chiếu.

PCB, schematic, layout, BOM, Gerber, fabrication, HIL và thay đổi runtime feature không thuộc bước này.

## 2. Server bootstrap

`components/lux_web/src/web_server.c` khởi tạo HTTP server với tối đa 20 URI handlers và custom WebSocket URI matcher. Sau khi server được tạo, bootstrap lần lượt đăng ký `web_routes_register(server)`, `otaManagerRegister(server)` và `web_websocket_init(server)`. Nếu một registration lỗi, server initialization thất bại.

| Server surface | Registration source | Current status |
|---|---|---|
| Core HTTP routes | `components/lux_web/src/web_routes.c` | Active registration |
| OTA routes | `components/lux_net/src/ota_manager.c` | Active registration |
| WebSocket route | `components/lux_web/src/web_websocket.c` | Active registration; behavior depends on `CONFIG_HTTPD_WS_SUPPORT` |
| Static assets | `web_routes.c` → `web_assets.c` | Active allowlist with two known text assets |
| Generated asset hook | None found in current PlatformIO/CMake path | Not present |

The web component directly compiles `src/web_server.c`, `src/web_routes.c`, `src/web_frontend.c`, `src/web_websocket.c`, `src/web_assets.c` and `src/ws_frame.c` through `components/lux_web/CMakeLists.txt`. No generated include directory, asset command, `extra_scripts`, `add_custom_command` or `configure_file` path is present.

## 3. HTTP route inventory

The following table is the complete route registration in `web_routes_register()` at the baseline. `/assets/*` is a wildcard route; its actual allowlist is listed separately below.

| Method | URI | Handler | Response/source | Request/API contract notes |
|---|---|---|---|---|
| GET | `/` | `index_get_handler` | `text/html`; `web_frontend_get_index()` | Dashboard HTML; references `/assets/style.css` and `/assets/app.js` |
| GET | `/config` | `config_get_handler` | `text/html`; `web_frontend_get_config()` | Configuration page |
| POST | `/config` | `config_post_handler` | JSON `{"status":"ok"}` on success | JSON body; max 8,192 bytes; imports config and saves NVS; 400/500 errors on validation/save failure |
| GET | `/setup` | `setup_get_handler` | `text/html`; `web_frontend_get_setup()` | First-time WiFi setup page |
| POST | `/setup` | `setup_post_handler` | JSON status/message, then reboot | Form-like body with `ssid` and `psk`; max 2,048 bytes; saves WiFi/config, stops captive portal and reboots |
| GET | `/firmware` | `firmware_get_handler` | `text/html`; `web_frontend_get_firmware()`; `Cache-Control: no-store` | Signed firmware upload UI; references OTA endpoints |
| GET | `/info.json` | `info_get_handler` | `application/json` | Fields include `device`, `firmware`, `board`, `ip`, `netmask`, `gateway`, `ssid`, `rssi`, `heap_free`, nested `config` |
| GET | `/wifi/scan` | `wifi_scan_get_handler` | `application/json` array | WiFi scan records with `ssid`, `rssi`, `authmode` |
| GET | `/setup/scan` | `wifi_scan_get_handler` | `application/json` array | Alias to the same WiFi scan handler |
| GET | `/health` | `health_get_handler` | `application/json`; `Cache-Control: no-store` | `status: ok` and per-output `enabled` values |
| GET | `/dmx.json` | `dmx_get_handler` | `application/json`; `Cache-Control: no-store` | Array of output snapshots with `output` and 512-slot `data` |
| GET | `/version.json` | `version_get_handler` | `application/json`; `Cache-Control: no-store` | Fields `version`, `channel`, `otaInProgress` |
| POST | `/reboot` | `reboot_post_handler` | `application/json`; `Cache-Control: no-store` | Sends `{"ok":true}`, delays, then restarts |
| GET | `/assets/*` | `assets_get_handler` | MIME inferred from suffix; content from `web_assets_get()` | Unknown resources return 404; current known allowlist has only two resources |

The current firmware route layer does not register `/setup` and `/setup/scan` as a separate web application namespace. They are part of the same HTTP server as the dashboard/operator routes.

## 4. OTA route inventory

OTA routes are registered separately by `otaManagerRegister()` during the same server bootstrap. They are used by the inline firmware page and are not static assets.

| Method | URI | Handler | Response/source | Contract notes |
|---|---|---|---|---|
| GET | `/ota/status` | `ota_status_handler` | `application/json`; `Cache-Control: no-store` | Fields `phase`, `pct`, `target`, `error`, `bootRetry` |
| POST | `/ota/upload` | `ota_upload_handler` | JSON success or HTTP error | Binary body; validates content length and OTA partition, writes/verifies image, sets boot partition and reboots; rate limiting returns 429 with `Retry-After` |

The firmware page polls `/ota/status` and uploads a `.bin` body to `/ota/upload`. The UI text and OTA behavior must remain separate from a future asset-generation decision.

## 5. WebSocket route inventory

The WebSocket module registers one route:

| Method | URI | Handler | Behavior |
|---|---|---|---|
| GET/upgrade | `/ws` | `ws_handler` | With `CONFIG_HTTPD_WS_SUPPORT`, accepts a connection and echoes `{"ok":true}` for text frames; without support, returns `426 Upgrade Required` and `WebSocket support disabled` |

The module can asynchronously send a fixed status frame containing `meta`, `state`, `senders` and `log`. This is an active protocol surface even though it is not an HTML/CSS/JavaScript asset.

## 6. Live static-resource allowlist

`web_assets_get(uri)` currently serves exactly these known resources through `/assets/*`:

| URI | Current source | MIME behavior | Consumer references |
|---|---|---|---|
| `/assets/style.css` | Inline CSS string in `components/lux_web/src/web_assets.c` | `text/css` | Inline index/config/setup/firmware HTML |
| `/assets/app.js` | Inline JavaScript string in `components/lux_web/src/web_assets.c` | `application/javascript` | Inline index/config/setup/firmware HTML |
| Any other `/assets/*` | No content; returns `NULL` | 404 from route handler | No confirmed live consumer |

The route handler has suffix branches for `.ico` and `.png`, but the current `web_assets_get()` allowlist has no corresponding content entries. These MIME branches are therefore capability scaffolding, not evidence that icon or PNG resources are currently served.

## 7. Inline HTML frontend resources

The current HTML pages are compiled C string literals in `components/lux_web/src/web_frontend.c`:

| Resource/function | Approx. role | Inline dependencies |
|---|---|---|
| `index_html` / `web_frontend_get_index()` | Dashboard/device and network status | `/assets/style.css`, `/assets/app.js`, `/config`, `/firmware` |
| `config_html` / `web_frontend_get_config()` | WiFi/device settings and advanced actions | `/assets/style.css`, `/assets/app.js`, config/reboot UI |
| `setup_html` / `web_frontend_get_setup()` | First-time WiFi provisioning | `/assets/style.css`, inline setup script, `/wifi/scan`, `/setup` |
| `firmware_html` / `web_frontend_get_firmware()` | Firmware upload and OTA progress | `/assets/style.css`, inline OTA script, `/ota/status`, `/ota/upload` |

The setup and firmware pages contain page-specific inline JavaScript. They are not represented as separate tracked HTML files under `webui/`.

## 10. Next gate

This document is the input to M0.4.5.2. The next package must produce a route/page/API/asset parity matrix and must not silently select `webui/` as canonical. For each route/resource, the matrix must identify the current consumer, candidate source, required DOM/API behavior, MIME/cache/security contract and migration owner.
